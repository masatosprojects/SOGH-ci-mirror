# SOGH 模擬面接 Sandbox（v0・隔離した試作）

**区分：`SYNTHETIC_ONLY`・`SELF_VALIDATED`。** Issue #75（M1 と隔離した試作の並行、ユーザー承認 2026-11-01）の v0。**架空の大学・方式・資料・報告・質問だけ**を使う、テキストの模擬面接。決定的なモックで、外部の AI・音声・映像 API・ネットワーク・保存・SOGH の運用DB・`src/db_contract` のいずれにも接続しない。**M1 の 8 ゲートとは無関係**（M1 は 2/8、NOT ACCEPTED のまま）。合成試験の合格は、実際の受験生での検証でも、面接の質の証明でもない。

## 動かし方
```bash
cd sandbox
python -m interview_sandbox --case fiction-ac-1            # 自分で答える（空の行で終了）
python -m interview_sandbox --case fiction-rec-2 --script answers.txt   # 1 行 1 回答のデモ
```
ケース：`fiction-ac-1`（架空・総合型：面接あり・10 分、日程と評価観点は未確認）／`fiction-rec-2`（架空・学校推薦型：面接あり、時間と形式は未確認）／`fiction-gen-3`（架空・一般：**面接は確認できない**ので「一般的な面接練習」と表示）。試験：`python -m pytest tests/test_interview_sandbox.py`。

## 体験の流れ（Issue #75 の必須 9 項目）
1 ケースを選ぶ → 2 `briefing()`：公式に確認できた条件／**未確認の事項（推測しない）**／受験経験（別枠・「1 件のみ。傾向とは言えません」）／ご注意 → 3 `start()`：最初の質問 → 4 `answer()`：**回答の言葉を引用した追質問**（曖昧な言葉→具体化、活動→自分の役割、理由が無い→理由、短い→経過）→ 5 深掘りの上限（質問ごと・全体）と残り時間（時間切れは回答の後に区切って終わる）→ 6 終了 → 7 `feedback()`：練習用ルーブリック 5 項目の**段階**（点数ではない）、各項目に**回答の該当箇所**（位置を記録）→ 8 改善の例（本人の言葉を組み替え、事実の部分は〇〇と空欄。経験・数字を作らない）→ 9 `retry()`：同じ条件でやり直し、`compare()` で前回との差（判定できない項目は変化に数えない）。

## 型と表示の分離
`OfficialFact`（公式。版つき。未確認は `unknown` で値なし）／`ExperienceReport`（個人の経験。公式事実と別枠）／`PracticeQuestion`（AI の練習素材。「実際の出題とは限りません」）／利用者の入力（メモリ内のみ）。公式事実に触れる質問は、その事実と版を表示し、未確認なら「公式には確認できていません」と出す。

## 守る線（`guards.py`・試験で固定）
禁止する表現：合格確率・合格の断定・大学公認（否定形は可）・完全再現・再現度の数値・必ず出題・実際の面接と同じ。**「過去問」「頻出」「傾向」と呼ばない**。家庭・宗教・思想・健康などの個人的な事柄は**追質問せず、フィードバックにも引用しない**。電話番号・メールアドレスは**伏せてから保持**し、ログには**件数と記号だけ**を出す。外部 API と保存は既定で無効で、有効化しようとすると `NotImplementedError`。パッケージは `sqlite3`・`socket`・`urllib`・`subprocess`・ベンダー SDK などを import せず、SOGH のコードを参照しない（試験で静的に確認）。

## 人手評価の準備（Issue #75 の手順 3）
`sandbox/evaluation/`：架空の回答台本 6 本（具体的・曖昧・短い・理由なし・個人的な事柄・面接の無い方式）をモックに通し、**評価者が空欄を埋める評価シート**（追質問の適合・踏み込みすぎ・該当箇所・改善例・断定的な表現・ルーブリックの各項目）を作る。`agreement` は、人の段階とモックの段階の一致（完全一致・1 段階以内）を、**人が評価した後にだけ**計算する（評価が無ければ `not_run`で、数字は出さない）。**まだ誰も評価していない**。

## 限界・未検証・改善課題（`NOT_RUN` を含む）
- **利用者の検証は未実施**（`NOT_RUN`）：追質問の妥当性・フィードバックの役立ち度・再挑戦の意欲・完走率は、人の評価セットと同意つきの試験が要る（外部参加者の募集前に同意・年齢・データ管理を決める＝ユーザーの決定）。
- **ルーブリックの妥当性は未検証**：段階の規則は単純な見える規則（文字数・数字・語の有無）で、**質の高い面接評価の代わりではない**。`clarity` は長さの目安が中心で、v1.1 で広い言葉（「いろいろ」「頑張った」等）だけの短い一文を、v1.2 で**数字が同じ文にあっても広い言葉は救われない**こと（「いろいろな活動を3回頑張りました」）と、断定の言葉（「絶対」「必ず」）を「一部できている」に下げた。広い言葉も断定の言葉も使わない曖昧な短文や、抽象的でも意味のある文は、規則では区別できず「明確」と判定し得る（これは人が判断する）。**規則に求められること（客観）と、人にしか判断できないこと**は `sandbox/evaluation/clarity_cases.py` の表で分け、版ごとの結果の履歴（改善・悪化した事例）を残している。人の評価との一致率は未測定（評価シートは空欄）。
- **個人情報の伏せ字の範囲と限界**：電話番号（ハイフン・空白・全角・`+81`）、メールアドレス（全角の `＠`・`(at)` を含む）、リンク、アカウント名（`@…`）、郵便番号（`〒…`）は、保存・追質問・フィードバックの前に伏せる（試験：`tests/test_sandbox_pii_masking.py`）。**氏名と住所は自動では伏せられない**（大学名・学校名と区別できず、誤検出が多い）。画面と注意書きで、入力しないよう求める。氏名・住所の自動検出は未実装で、人の確認が要る。
- **v1.2 で直した欠陥**：回答に「合格できます」「必ず聞かれる」「大学公認」などの、このツールが言ってはいけない断定が**含まれていると**、v1.1 では追質問とフィードバックが例外で止まり（利用者の自分の言葉に対してガードが働いていた）、セッションが進められなくなった。v1.2 では、そのような言葉を**引用せず**（中立的な追質問と注意書き `claim_not_repeated` に置き換え、フィードバックの該当箇所は位置だけを残して伏せる）、ツール自身が断定しないことは変えない。
- 音声・映像・実時間の応答・LLM による質問生成は**未実装・未承認**（Issue #67、有料 API の事前承認が要る）。
- 入試事実 DB との接続は**未実装**。将来は M1 が受け入れた読み取り契約（版固定・unknown・根拠）の**読み取り専用スナップショット**だけを入力にする（`docs/PRODUCT_STRATEGY.md` の合流条件）。
- 実在の大学・方式の情報は一切含まない。大学・方式ごとの質問の妥当性は検証されていない。
