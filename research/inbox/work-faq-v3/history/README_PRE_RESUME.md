## 確定契約（登録簿1.6.0、PR #43）

| 提案項目 | 原文からの値 | 対象と例外 |
|---|---|---|
| ai_text_underline_required | true | AIが実際に生成/修正した文章。間接的な影響箇所も含む。文章チェックも対象 |
| simple_spellcheck_underline_required | false | 文書校正機能による単純な誤字脱字修正のみ。AI内容生成一般の免除ではない |
| human_advice_underline_required | false | 他人の添削・助言による修正。AIの修正とは別の条件 |
| human_advice_activity_report_required | true | 上記の人による添削・助言は活動経過報告書に記載必須。下線免除と報告義務を区別 |
| ai_visual_disclosure_required | true | AI生成の画像・図・表。説明文や脚注に明示。文章の下線とは別の義務 |

全項目boolean。旧データ保全のため登録簿では任意・null不許可と確定。不明はfalseではなく省略/保留。今回の抽出プロファイルでは5項目すべてに6つの引用参照（一意な原文範囲は5箇所）を関連付け、欠落・曖昧・別節の引用なら登録しない。確定したマージ版9856213に従い、新根拠1版を正式登録した。

`field_proofs` に値、actor、action、適用サイクル、例外、`proofs`配列の位置を保持する。各proofはHTMLの正規化位置と短い原文引用を保持する。boolと引用の極性・対象・例外が一致しない場合はWorkの登録前検査でも拒否。全ページ本文はローカル専用。

## 独立実装と検証

- `faq_policy.py`: 一意なAC節と原文箇所から極性を導出。原文から判断できない値を作らない。文章は確認された値から生成する。現在の正しい3つのFAQ説明文は旧版と一致する。
- `supplements.contract_state`: fact_keyがactiveでも新しい5項目の型契約が登録されていなければpending_contract。未登録の値を警告だけで有効化しない。
- `revisions.stage`: boolと原文の結び付きを再確認。有効化は入力/記事/QAのハッシュと前状態が一致した場合のみ。旧v0.5をコピーしたv0.6作業DBで実行し、旧50根拠/13草案は保全。
- `revise_notices.py`: pendingしかない場合に既存headがあることだけを理由にapproved=trueと報告しない。候補/有効状態を分ける。
- `notice_articles.py`: ACの提出書類/面接準備の記事で、編集助言の前に公式FAQの条件と例外を配置。他方式には挿入しない。通常の同入力再実行は0登録/0改訂。明示的再承認やロールバック後の再承認は承認イベントIDで履歴の衝突を防ぐ。

DBの既存表は変更しない。新しい条件は後方互換のあるrecord JSONと既存の改訂テーブルへ追加する。旧根拠を上書きせずparentを保存し、有効ビューでは旧FAQ版を新FAQ版へ置き換える。

## 再現手順

配布物のpipelineで実行。原本/実DB/QAリポジトリは別途ローカルで指定する。原本HTML、SourceSnapshot、SQLite、秘密情報をGitHubへ置かない。

```powershell
python -B -m pytest tests -q -p no:cacheprovider
python -B scripts/revise_notices.py --specs config/faq-structured-v3.json --monitor-root <FAQ収集状態> --base-export <元の46根拠と原記事JSON> --base-db <旧v0.5> --work-db <別のv0.6作業DB> --qa-root <契約確定コミットのQA保存先> --output <新規結果ディレクトリ> --as-of 2026-11-01
python -B scripts/export_active.py --database <v0.6> --base-export <元の46根拠と原記事JSON> --output <新しい全体ビュー>
python -B scripts/audit_faq_mutations.py --before <旧50根拠13草案> --after <新しい全体ビュー> --qa-root <同じ確定QA> --output <新規検査ディレクトリ>
```

取得が24時間より古い場合は再取得と版の確認が必要。基準日を未来日に変えて鮮度を確認したことにしない。契約未確定ならexit1/pendingとなり有効化しない。出力先は毎回新規。
