# 原典の証拠の種類と、それが支えてよい主張（Claude、2026-11-02）

目的：原典に関する「確認した」が混ざらないように、**証拠の種類を 8 つに分け、それぞれが何を支え、何を支えないか**を固定する。M1 の正式な受け入れ契約・8 ゲートは変更しない。登録器（`source_verification_events` の 4 水準）に対応づける。PR #94 の R-1（手書きの観察ファイルで真正性が pass になった）の再発防止の基準。
**状態：設計の基準（Claude 案）。Work の実装がこれに沿うかは試験（`tests/test_pr94_source_registration_review.py`）で確認する。新しい水準・スキーマの導入は、Work・ユーザーの合意が要る。**

## 1. 8 つの証拠
| # | 証拠 | 何を支える | 何を支えない | 登録上の水準（`level`） |
|---|---|---|---|---|
| 1 | **保存原典の SHA 一致**（保存ファイルのバイトの SHA-256 が、記録の SHA と同じ） | 記録が指すバイトを今も持っている | 公式サイトが出したものか、内容が正しいか | `bytes_match_recorded_sha`（pass 可） |
| 2 | **保存原典からの引用位置の一致**（頁・正規化後の位置・引用文が、保存バイトの抽出テキストと一致） | 記録の引用が、その抽出器・正規化で、その位置にある | 別の抽出器で同じ位置になること／内容の意味 | `stored_file_matches_record`（pass 可）。位置は `extractor_id`＋`normalization_id` とセットでのみ意味を持つ |
| 3 | **過去の保存原典と、現在取得した文書の差分**（バイト一致・正規化本文の一致・引用の存在） | 「同じか違うか」の**比較の事実** | 旧保存版の真正性（本文が同じでもバイトが違えば別の版）／現在版が正しいこと | 水準を**上げない**。比較の報告だけ |
| 4 | **呼び出し側が提供した観察 JSON** | 比較の**入力**（別の実体のファイルで、SHA が申告と一致するもの） | 公式取得の証明。フラグ（`robots_checked`／`final_url`／任意の「確認済み」）は**自己申告**で、読まない | 水準を**上げない**（`not_run` のまま） |
| 5 | **Collector 自身の実行証跡**（同じプロセスで呼んだ Collector の戻り値と、その Collector が書いた受領行〔`collection.sqlite` の `observations`〕の全項目一致） | 「このプロセスが、この URL から、この時刻に、このバイトを取った」 | 同じ権限で Collector・Python プロセス・受領ファイルを書き換える主体への耐性（D2/G-08） | 6 の**前提**であって、それ自体は水準ではない |
| 6 | **現在の公式サイトから取得したバイトの真正性** | 5 を満たし、https・ホスト許可・最終 URL＝要求 URL・robots 確認・サイズ上限・取得時刻が**この取得の窓**に入り、取得物が保存原典と別の実体で、**バイトが保存版と同一**のときだけ、**保存版**の真正性 | 別バイトのとき：旧保存版の真正性（`not_run`）。現在版は**別の版**で、別の SHA として登録候補にする | `official_site_authenticity`（上の条件のときだけ pass） |
| 7 | **内容が実際の入試条件を意味すること** | 値・条件・例外が原典の記述と一致する（独立した読み） | AI による読みは人の確認の代わりではない。年度・方式への適用は別 | `content_meaning_checked`（**登録器は書かない**。独立 QA／人の確認の後に別の手順で。それまで `not_run`） |
| 8 | **入学年度・方式・学部への適用が確認できたこと** | その原典が、そのケースの年度・方式に適用される | 原典が年度・学類を明記しないとき（FAQ・慶應告知など）は、ケースの対応づけは推測であり、**年度付きの要項との照合が要る** | 水準ではなくメタデータ（`applies_to_fiscal_year`）＋別の照合。明記が無ければ NULL のまま |

## 2. 規則（試験で守らせる）
1. **自己申告は証拠ではない。** 手書きの JSON のフラグ・自己宣言の項目（`official_fetch_observation`、`provenance_kind` など）は、どんな値でも水準を上げない。
2. **保存原典自身を「現在の取得物」にできない**（同じパス、シンボリックリンク、ハードリンク）。比較にならない。
3. **時刻は、タイムゾーン付きで、未来でなく、live の場合はこの取得の開始から現在までの範囲**。日付だけ・不正な形式・None は拒否。
4. **バイトが違えば、旧保存版の真正性は推測しない。** 正規化本文が同じでも、バイト一致とは区別して報告する。
5. **live でも `content_meaning_checked` は上げない。** 真正性と意味は別。
6. **live と呼び出し側 JSON は同時に指定できない。** live の確認は、明示した実行（`--verify-official-live`）だけ。
7. **ネットワークの無い CI では live の本物の取得は試験できない。** CI では、本物の Collector と同じ契約の**模擬**（戻り値＋受領行）で、受理・拒否の論理だけを試験する。本物の取得はローカルの明示の実行で、結果は `SELF_VALIDATED` であり、独立 QA が公式取得を確認したことにはならない。
8. **限界**：同じ OS アカウントで動く主体は、Collector・Python・受領ファイルを書き換えて偽装できる。これを防ぐのは認証（署名・別アカウント・別端末）で、`docs/THREAT_MODEL_D2_G08.md` の決定事項。ここで定義した pass は「この実行の中で矛盾が無い」であって、敵対的な主体に対する真正性の保証ではない。

## 3. 今回の 3 件への適用（2026-11-02 時点）
筑波 FAQ・慶應告知は、**HTML でバイトが保存版と異なり**、live でも旧保存版の真正性は `not_run`。筑波返還 PDF は、live でバイトが同一のとき**だけ**保存版の真正性を pass にできる。いずれも `content_meaning_checked` は `not_run`、FAQ・慶應告知の年度・学類は未確認（8）。
