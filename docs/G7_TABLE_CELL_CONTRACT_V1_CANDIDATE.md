## 4. 新しい `fact_key` の承認の境界
`fact_key`（例：区分ごとの募集人員）は、レジストリの必須項目（定義・単位・粒度・必須の根拠の種類・値の型・年度の扱い）を添えて**ユーザーと Work と Claude が合意してから**登録する。合意の前は、本検査が E-FACTKEY で止める。既存の `fact_key`（学部全体の募集人員など）に**区分ごとの値を流用しない**（粒度が違う）。

## 5. 限界
単語の矩形の順序づけであって、完全な表認識ではない。信頼の境界は「人がレビューしたプロファイル＋原典の SHA」。回転した頁・図形だけの数字・スキャン（OCR）・結合セルの途中で切れた表・別版の SHA は拒否（別のレビュー済みプロファイルが要る）。検査は意味（その数字が何を指すか）を判断しない。罫線は呼び出し側が独立に導いた値（Claude の再現手順）を渡す前提で、無ければ E-RULING は走らない。
