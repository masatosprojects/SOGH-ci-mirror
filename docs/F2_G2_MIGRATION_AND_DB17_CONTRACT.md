**ラベル：契約案（`SELF_VALIDATED`／Claude の提案。合意前）。** 移行の SQL ファイルは**リポジトリに追加しない**・運用 DB へ**適用しない**・凍結済みの 0002〜0009 は**変更しない**。F-2 の正式な復元・受容は別の判断（本書の対象外）。M1 は 2/8（g4・g8）、NOT ACCEPTED。
根拠：PR #96 head `6f46a20`（G-1・G-5 修正を確認済み）と Work の `G1_G2_PROPOSAL.md`、`docs/F2_RESTORATION_CONTRACT_PROPOSAL.md`（案 1）。
**実行できる仕様**：`tests/test_f2_archive_db17_prototype.py`（18 件）。試作の移行を**テストの中だけ**に登録し、使い捨てコピーで次を確かめた（リポジトリには何も足していない）。

## 0. いま分かっていること（試作で実証）
- DB-17 は「所有プレフィックス（`trg_` `ux_` `ix_` `v_`）の中の、どの移行も作っていない物」だけを**余分**として報告する。Work の `work_f2_*` は範囲外なので、**表・トリガーが消えても、別物に差し替わっても、余分が増えても DB-17 は pass のまま**（試験で再現）。
- 解決は「Work が名前を変えて回避する」ことではなく、**(a) 追加の移行 `0010` が作った物として登録し、(b) `work_f2_` を所有プレフィックスに加える**こと。両方そろうと、試作では次がすべて DB-17 の**失敗**になった：ガードの削除、弱いガードへの差し替え、表の差し替え、所有名前空間の余分な索引・トリガー、`user_version` の巻き戻し。
- (b) だけ（移行なし）や (a) だけ（プレフィックスなし）では不十分：(a) だけだと余分な物は見えない（試験で確認）。
- 所有プレフィックスに入れると、**移行の前に作られた無防備な `work_f2_*` を持つ DB は「ドリフト」として移行前に拒否**される（ファイル不変・試験で確認）。事前検査（preflight）は二重の防御。

## 1. 契約（実装の受け入れ条件。Work が SQL を書き、Claude が下の試験で独立に確認する）
| # | 条件 | 具体的な要求 | 確認方法 |
|---|---|---|---|
| 1 | **スキーマの所有範囲** | `work_f2_recovered_rows` 1 表と `work_f2_*` の 4 トリガーだけ。`work_f2_` を DB-17 の所有プレフィックスに追加（`src/db_contract/additive_schema.py::_OWNED_PREFIXES`、Claude 側の変更）。他の物（索引・ビュー）は足さない／足すなら同じ移行で列挙。ワイルドカード除外・別名での回避はしない | 試作の「余分な物は失敗」「名前空間外は無関係」 |
| 2 | **固定マニフェスト** | 移行の SQL には**行を含めない**（構造だけ）。行は承認済みの回収ツールが入れる。マニフェスト（旧コピー 4 件の SHA・行数・ペイロード SHA・スキーマ SHA）は**ハッシュだけ**を Git に置き、行の内容・旧記事本文は置かない。Real36 の既知値：ペイロード `7a7ed658…bd3f`、スキーマ `395a8cbc…e5ae0`（Work の報告）。**検査側（DB-19 候補）は、マニフェストを引数で受け取り、報告に使ったマニフェストの SHA を記録する**（コードに固定しない） | Claude が旧コピーから独立に再計算した多重集合（36 行）との一致（`tests/test_pr96_f2_recovery_review.py` の既存の検査）。マニフェストの SHA がレポートに出ること |
| 3 | **INSERT の能力ゲート** | INSERT は専用の能力関数（`work_f2_insert_allowed`）が 1 を返す接続だけ。この能力は `sogh_write_ok` とは**別**（アーカイブへの書き込みが一般の書き込みの能力で通ってはならない）。素の接続は「no such function」で拒否。UPDATE／DELETE は能力があっても拒否。**能力は認証ではない**（登録できる主体は止められない。D2/G-08）。許可行は完全なペイロードの許可リスト（固定マニフェスト）に限る | 試作の「素の接続は INSERT 不可」「能力があっても UPDATE／DELETE は append-only で拒否」。Work の 25 件の試験と私の 34 件 |

## 2. 手順（合意が取れたあと。Claude／Work／ユーザーの分担）
1. **ユーザー**：状態 A（アーカイブの保全）を正式な移行に載せる方針の承認（運用 DB へは適用しない）。
2. **Work**：`0010` の SQL（表＋4 トリガー＋能力関数を使う INSERT ガード）を、既存の Work の定数から**生成**して凍結ファイルにする案を出す（行は入れない）。Claude はレビューするだけで、SQL を発行しない。
3. **Claude**：`_OWNED_PREFIXES` に `work_f2_` を加え、`MIGRATIONS` に 0010 を登録する小さな PR と、試作の試験を**本物の SQL に向けた試験へ置き換える**（同じ 18 件の主張。Work の定数と一致するか、行を含まないか、チェックサム）。
4. **合同**：使い捨てコピー（v06 のクローン）で 0010 を適用 → DB-17 pass → Work の `--verify-archive` と Claude の独立再計算で 36 行の一致 → 上の改ざん試験 → 再実行 no-op。運用 DB へは適用しない。
5. **別の判断**：状態 B（30 行の復元）と D（F-2 の受容の署名）。
