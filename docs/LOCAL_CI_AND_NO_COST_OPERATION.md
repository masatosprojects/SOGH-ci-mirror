# 課金せずに作業を続ける運用（ローカル CI と、無料の代替手段）

**方針（ユーザー、2026-11-02）：これ以上お金を払わない。** GitHub Free の非公開リポジトリの Actions は、月の無料枠を使い切ると、追加利用の上限が 0 円のため止まる（支払いの失敗ではない。Billing で確認済み）。無料枠が戻るまでの間も、作業と統合が止まらないようにする。
**ラベル：運用の案と手順（`SELF_VALIDATED`）。ローカルの検査は「CI の成功」ではない。**

## 1. 使うもの：`scripts/local_ci.py`（無料・標準ライブラリのみ）
`.github/workflows/tests.yml` と**同じ手順**を、この計算機の**まっさらなチェックアウト**（作業ツリーの未追跡ファイルに助けられない）で実行する：任意の追加ライブラリ（pymupdf）を隠し、`pytest tests/ -q -rs`、skip を失敗とする回帰レポート、全体ビュー、Work の全体ビュー CLI。結果の最後に、**どの CI ジョブの環境を覆ったか／覆っていないか**を必ず表示し、`this_is_not_a_green_ci: true` と出す。
```
python scripts/local_ci.py                          # 現在の HEAD
python scripts/local_ci.py --ref origin/master --merge origin/claude/topic-a --merge origin/claude/topic-b
python scripts/local_ci.py --python <Python 3.11 のパス>   # 3.11 の環境を覆う
```
統合の手順（Claude の PR）：①まとめて 1 回実行（複数の PR を `--merge` で合わせる）→②成功なら、各 PR に「ローカルで実行：環境・件数・未確認の環境」を書く→③統合。ユーザーの承諾が前提（2026-11-02 に取得済み。**CI の条件の緩和はこの範囲だけ**）。Work の PR は Claude は統合しない。

## 2. 覆えない環境と、無料で覆す方法
| 環境（CI のジョブ） | いま | 無料の方法（実行にはユーザーの許可が要るもの） |
|---|---|---|
| Windows・Python 3.12（`pytest-windows`） | **覆える**（この PC） | — |
| Python 3.11（`pytest-py311`） | **覆える**（2026-11-02 に公式インストーラー 3.11.9〔署名確認済み〕を `O:\py311` に導入。`python scripts/local_ci.py --python O:\py311\python.exe`。master で 1532 件成功） | — |
| Linux・Python 3.12（`pytest`） | 覆えない（WSL に Linux が無い） | WSL に Ubuntu を入れる（数百 MB〜1 GB 台のダウンロードと設定変更） |
| どれも | — | **自前の実行機（self-hosted runner）**：自分の PC を GitHub Actions の実行機にする。**自前の実行機の時間は無料**。ただし、登録トークンの発行・常駐プロセス・リポジトリのコードを自分の PC で実行するリスクがあり、Linux ジョブは別の OS が要る。ユーザーの判断事項 |

## 3. CI の消費を減らす案（ワークフローの変更。ユーザーの承諾後に PR で）
消費の主因は、**同じ内容を何度も走らせること**と、Windows ジョブ（Linux の約 2 倍の時間として計上）。
1. **文書・報告だけの PR は CI を走らせない**（`paths-ignore`：`**.md`、`docs/**`、`reports/**`）。私の PR の多くは文書と条件つきの試験で、効果が大きい。
2. **`master` への push で毎回 3 ジョブを再実行しない**（PR で検査済みの内容の再実行）。週 1 回の `schedule` は残し、ドリフトを見る。
3. 再実行・やり直しを減らす（PR をまとめる。ローカルで先に通す＝本書の手順）。
4. 試験の高速化（重い試験のうち、同じ事実を二重に見ているものの整理）。
これらは**検査の網羅を落とさない範囲**で。変更は `.github/workflows/tests.yml` で、CI が動かない間は効果を確認できないので、**ユーザーの承諾と、復旧後の確認**が前提。

## 4. 他の無料の代替（採らないもの、注意）
- **リポジトリを公開にする**（公開リポジトリの Actions は無料）：非公開の資料・データ・内部文書が公開されるので**採らない**。
- **他の CI サービスの無料枠**：コードと資料を外部のサービスへ送ることになるので、ユーザーの判断なしに使わない。
- **有料プランへの変更・予算の引き上げ**：しない。

## 5. 限界
ローカルの検査は、**同じアカウント・同じ PC の中の確認**で、CI が与える「別の環境での再現」の代わりにはならない。過去に CI だけが見つけた問題（改行の違い、環境にない依存）は、まっさらなチェックアウトと依存の隠蔽で多くを補うが、Linux・3.11 の差は補えない。無料枠が戻ったら、各 PR の CI を再実行して確認する。
