# SOGH 開発マスタープラン（工程P0〜P10・Work Package）

> `docs/development_progress.json` から自動生成（`python -m src.db_contract.progress --write`）。手で編集しない。

最終目標：大学の公式一次情報を継続的に収集・検証し、対象年度・入試方式ごとに版管理されたDBへ登録し、根拠付きのnote記事を生成し、**人の承認を経て**非公開下書き・公開・訂正できる、再現可能で監査可能な継続運用サービス。「DB完成」は全国の大学を登録し終えた状態ではなく、**新しい大学・年度・様式を設定で足しても、スキーマと品質保証を作り直さずに済む**状態を指す。

```text
公式情報の取得 → 版管理 → 原典に基づく事実の抽出 → 大学・方式・年度別のDB登録 → 条件・例外の構造化 → 独立QA → DBの安全な有効化
→ 記事企画・生成 → 記事の独立QA → 人間の承認 → note非公開下書き → （別途承認で）公開 → 公式情報の変更監視 → 影響記事の改訂・再検証・訂正
```

進め方：日付ではなく**依存関係と完了条件**で動かす。状態は `not_started / design / implementing / blocked / QA_pending / accepted / operational`。`accepted`（受け入れ済み）と `operational`（運用で実証済み）は別。

規則：（1）進捗は、工程ごとの受け入れ条件（criteria）のうち、証拠つきで verified のものだけを数える。テスト件数・PR数は進捗ではない。　（2）合成DB／リポジトリのサンプルでの成功は、実データでの検証（real_data）に数えない。未確認・未実施は加算しない。　（3）state の accepted（受け入れ済み）と operational（運用で実証済み）は別。operational は限定運用（P9）以降でしか付けない。
