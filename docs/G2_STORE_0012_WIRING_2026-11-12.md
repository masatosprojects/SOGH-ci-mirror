## 何が足りなかったか

移行 0012（`faq_unconfirmed_evidence`、追記専用、`scope_status` は 'unknown' 固定、昇格経路なし）は DB チェーンに存在するが、Work のパイプラインの `EvidenceStore`
（stage-1 と g2 パッチ適用後）には、適用範囲が未確認の公式 FAQ の根拠をこの表へ書く経路がなかった。

## 何を変えたか

`patches/g2-faq/work-store-0012-wiring.patch`（第3のパッチ。変更は `admissions_pipeline/store.py` の1ファイル、末尾にメソッドを追加するのみ。CRLF は原本どおり）。

`EvidenceStore.record_unconfirmed_faq_evidence(record, storage_case_id, recorded_by, recorded_at=None)`:

- 入力検証は g2 のモジュールに委ねる: `is_unconfirmed_faq`（scope_status が 'unknown' の tsukuba-ac-faq-v1 記録のみ）、`validate_condition_bindings`（case / 年度 / 学類 / 学科の束縛を持つ記録は拒否: STR-076）。加えて `case_id`・`fiscal_year`・`faculty`・`department`・`exam_year` のいずれかが入った記録は拒否（STR-099/100/101）。適用年度・学類・方式を主張する経路はなく、`scope_status` は常に 'unknown'。
- 1つの proof につき1行（`evidence_id = <記録の evidence_id>:p<n>`）。`question_sha256` は proof の直近の質問見出し（正規化後）の SHA-256。引用・正規化オフセット・ページは記録のとおり。
- `storage_case_id` は**保管先の管理用参照**（STR-100）。その FAQ がその募集回に適用される証拠ではない。`admission_cycles` に存在しなければ拒否。`source_sha256` が `source_documents` に無ければ拒否（先に取り込む）。
- 書き込み先は `faq_unconfirmed_evidence` のみ。`facts` には書かない。UPDATE / DELETE / `INSERT OR REPLACE` / `INSERT OR IGNORE` / ON CONFLICT は使わない。
- 重複（同じ行 ID が既にある）は `ValueError("... duplicate ...")` で**全体を拒否**。1回のトランザクションなので、一部だけ書かれることはない。
- fail closed（`RuntimeError`）: 表が無い（移行 0012 未適用）、5つのガード（no_update / no_delete / no_replace / no_negative_rowid / not_a_fact）のいずれかが無い、接続が `sogh_write_ok` を登録していない（stage-1 の `configure_connection` を通っていない）。g2 パッチ未適用なら import で失敗する。

## Work が戻ってきたときの適用手順

順序: stage-1 → g2 → g2-unconfirmed-section → 本パッチ。各パッチの前に `git -c core.autocrlf=false apply --check` を使い、`pipeline/` ディレクトリで `git -c core.autocrlf=false apply --whitespace=nowarn <patch>`。
本パッチは store.py の末尾に追記するだけなので、前のパッチ無しでも文面上は当たるが、実行時に失敗する（順序は実行時に強制される）。適用後、Work のドライバが未確認 FAQ を保留する箇所からこのメソッドを呼ぶかどうかは Work の判断（本パッチはドライバを変更しない）。
対象 DB には移行 0012 が適用されている必要がある（適用は人間または Work の判断。本作業は運用 DB に触れていない）。
