# 根拠（evidence）の訂正版を作るときの契約案（PR #94 の訂正候補 S1〜S3 を受けて）

**ラベル：契約案（`SELF_VALIDATED`／Claude の提案。Work・ユーザーとの合意前）。** 訂正の適用・新しい根拠 ID の採番・運用 DB への登録は、本書では行わない（合意と独立レビューが先）。
独立の検査：`src/integration/evidence_correction_check.py`（読み取り専用）と `tests/test_evidence_correction_check.py`（29 件）。

## 1. 原則
1. **既存の根拠は上書きしない。** 訂正は「前の版を指す新しい版」を作る。前の版（`evidence_id`・`record_sha256`）は残り、置き換えの履歴は読める。
2. **同じ原典（SHA）に対する訂正だけ。** 原典が変われば訂正ではなく「新しい根拠」。
3. **訂正してよいのは、原典の中の位置づけを表す欄だけ**：`/proofs/<n>/section`（見出し）、`/applicability`（適用範囲の記述）、`/published_date`（公開日）。引用文・位置・ハッシュ・原典・ケース・年度・値は訂正の対象外（変えるなら新しい根拠）。
4. **推測で埋めない。** 原典に無い年・日付を訂正後の値に入れない。分からないなら `null`／「未確認」とし、その理由を残す。
5. **意味の確認とは別。** 訂正が原典に根ざしていること（本書の検査）は、訂正後の主張が正しいこと（`content_meaning_checked`）ではない。登録担当は後者を書かない（`docs/SOURCE_EVIDENCE_LEVELS.md`）。

## 2. 候補（提案）の必須項目
`predecessor_evidence_id`、`predecessor_record_sha256`（前の版の正規化 JSON のハッシュ）、`source_sha256`・`source_url`、`extractor_id`・`normalization_id`、`proposed_edits[]`（`path`／`old`／`proposed`）、`locators[]`（ページ・位置・`quote_sha256`・`source_page_text_sha256`）、`new_evidence_id: null`、`meaning_checked: not_run`、`requires_independent_review: true`、`applied: false`。

**ページ本文のハッシュの定義（固定する）**：`source_page_text_sha256` ＝ 抽出器が返した**生のページ本文**（正規化前）の UTF-8 の SHA-256。引用のハッシュ（`quote_sha256`）は、**正規化後**（文字ごとに NFKC、空白を除く）のページ本文の `[start:end]` の SHA-256。抽出器が変わればハッシュも変わるので、`extractor_id` を必ず添える。

## 5. 合意が要ること（Claude の提案、Work・ユーザーの判断）
1. **新しい根拠 ID の採番規則**（例：前の ID＋訂正の通し番号と訂正内容のハッシュ）。ID の生成は DB の契約側（Work）と合意。
2. **文書日付（document_date）の欄**を根拠の形式に持つか。いまの形式に無いため、持たないなら訂正は `published_date: null` と理由の記録だけにする。
3. **適用範囲（applicability）の「未確認」の表し方**（自由文か、列挙値か）。列挙値の方が下流の検査がしやすい。
4. 前の版を指す欄（`corrects`／`supersedes`）を、F-2 の履歴契約（`docs/F2_RESTORATION_CONTRACT_PROPOSAL.md`）と同じ仕組みに載せるか。
5. 訂正版の `official_site_authenticity` は、**前の版から引き継がない**（原典は同じでも新しい登録の観察ではない）。引き継ぐなら、前の版の観察へのリンクを明記し、新しい観察とは区別する。

## 6. 今回やっていないこと
訂正の適用、新しい ID の採番、運用 DB・監査コピーへの書き込み、意味の確認（`content_meaning_checked`）、他の根拠の訂正。**GitHub Actions は起動せず CI の結果はない**（ローカルのみ。Linux・Python 3.11 は未実行）。実データの試験は、監査コピーと保存原典がある計算機でのみ定義され、PDF の候補は PyMuPDF がある環境でのみ定義される（無ければ未定義であり、成功ではない）。
