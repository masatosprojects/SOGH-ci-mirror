## 1. 製品の目的と対象ユーザー
- 【U】SOGH の中核は、**大学・学部・入試方式別の AI 模擬面接**。記事の生成と note の投稿は、主として集客と情報提供の導線であり、**事業の中心は面接サービス**。
- 【U】対象は、大学別の面接情報が乏しく反復練習の機会も少ない受験生（高校生を含む）。学校の先生との練習を代替するものではない（`PRODUCT_STRATEGY.md` §2 の記録）。
- 【U】SOGH 独自の価値は、人物アバターや音声 LLM の自社開発ではなく、次の**結合**：検証済みの大学別入試情報 DB／同意・出所・年度を管理した受験経験情報／志望理由・研究計画に即した質問と追質問／面接時間・質問の深さ・進行の制御／根拠つきの個別評価と反復改善／将来の合格者・在学生との安全な交流。

## 2. Zoom 風の完成体験【U】（技術構成の承認ではない）
受験生はブラウザから面接室に入り、人間の姿をした AI 面接官と、リアルタイムの音声で模擬面接を行う。AI 面接官は、自然な唇の動き・視線・うなずき・待機の表情・適切な沈黙・自然な応答のタイミングを備え、**受験生の発言内容を理解して**、研究計画・志望理由・活動経験・論理的整合性・検証方法などについて追質問する。固定質問の読み上げではない。面接後は、実際の発言を根拠にした詳細なフィードバック・改善提案・再挑戦を提供する。
**常に明示する**：AI 面接官であること／練習であり、実在大学の公認面接でも、実際の出題の再現でも、合否予測でもないこと（既存の `guards.py` の禁止断定と `DISCLAIMERS` に整合）。
将来の選択肢【U】：面接官の人数、模擬面接の形式、研究発表型、時間設定、難易度。

## 3. 画面の構成【C】
| 画面 | 目的・必須要素 |
|---|---|
| **面接準備室**（lobby） | AI 面接官であること・練習用であること、**検証済みの条件と未確認の事項の別**（既存 `Briefing` の三区分：公式に確認できた条件／公式には確認できていない事項／経験報告）、データの扱いの同意（録音なし・映像なしが既定）、デバイス確認、面接の設定（時間・難易度・文字モード） |
| **面接画面** | 面接官の映像（または縮退の静止画・字幕のみ）、自分の映像（任意でオフ）、**残り時間**、字幕（任意）、**中断・休憩・終了・緊急停止**、文字モードへの切替 |
| **終了画面** | 終了の宣言（時間切れ／本人の終了／障害）、フィードバックの生成中表示（非同期）、保存しないことの確認 |
| **フィードバックと再挑戦** | 項目ごとの段階と根拠となる発言、改善の例、質問されなかった分野の明示（`feedback.py` の `notes`）、同じ条件での再挑戦（`retry()`）と前回との比較、限界の表示 |

## 5. AI 面接官の自然な振る舞い【U】＋制約【C】
- 求める挙動：話し終わりの待ち（考え中の沈黙で割り込まない）、短い相づち、自然な間、聞き手としての表情、割り込みへの即時の停止、時間警告。
- **緊張感は、時間の制約・質問の深さ・相手の反応・適切な沈黙から作る**。人格否定・威圧・詮索（家庭、宗教、思想、健康）を含めない（`guards.SENSITIVE_TERMS`）。
- **面接官側が受験生の発言を遮る演出は初期は入れない**（`INTERVIEW_SERVICE_RFC.md` §16.5 と同じ）。
- 表情・声色・見た目から、能力・人格・合否を推定しない（フィードバックにも使わない）。

- M1 の受け入れ前は、**架空データだけ**。実接続は M1 の g1・g2 などの受け入れと、`INTERVIEW_SERVICE_RFC.md` §14 の最小契約の合意後。
- PR #109 の読み取り契約（W3 v2）は**契約案・Draft**。`entry_year` と `exam_year` は別の概念で、Sandbox の `fiscal_year` への写像は**未合意**（本書で確定しない）。

## 9. プライバシー・同意・録音なしモード【C】（詳細：`docs/realtime-interview/THREAT_MODEL_AND_PRIVACY.md`）
既定は**録音なし・映像なし・保存なし**。送信先（事業者）・目的・保持・学習利用を同意画面に明示。未成年（高校生）を前提に最小化・削除・アクセス制御。法令・保護者の関与の要否は**未調査**（結論を書かない）。

## 10. リアルタイム会話の制御【C】
- 外側の状態（既存）：`setup → in_progress → ended`。内側の副状態（新規）：`interviewer_speaking／listening／deliberating／paused／degraded_text／reconnecting`。
- **世代 ID（`generation_id`）**で発話を管理。割り込みでは、音声生成・再生バッファ・映像の旧世代をすべて取り消し、遅れて届いた旧世代のパケットを捨てる（負例の試験を必須にする）。
- 発話は**検証済みの質問**（`ValidatedQuestion`）か、許可リストの固定文だけ。自由生成の音声は §11 の方式 B の制限に従う。
- 時間は**コントローラの単調時計**（ミリ秒）で管理。既存の `elapsed_seconds`（呼び出し側が渡す秒）との互換は `TurnEvent` で保つ。

## 11. 方式A／方式Bの扱い【C】（詳細：`docs/realtime-interview/PROVIDER_COMPARISON_2026-11-03.md`）
- **方式A**：音声認識 → LLM → **検証** → 音声合成 → アバター。発話前に全文を検証できる。遅延が積み上がる。
- **方式B**：リアルタイム音声モデル → アバター。自然さが期待できる一方、**生成音声の再生前に全文を検証できるとは限らない**（公式資料：Gemini の Live ネイティブ音声モデルは音声のみを出力し、テキストは出力の文字起こしから得る【公】）。
- **方針**：公式情報に関わる発話と、質問の本文は**常に方式A（検証済みの文を読み上げ）**。方式Bは、**許可リストの種類の発話**（相づち・つなぎ・「続けてください」・時間の案内の固定文）だけに限り、監査と遮断の仕組み（違反で即取り消し、固定文での復旧、方式Aへ切替）を前提とする。方式Bの全面採用は、検証できる範囲が確認されるまで承認しない。

## 12. 面接後の評価【C】
- `feedback.py`（規則ベース、ルーブリック v1.2）を**下限**として残し、LLM による詳細分析は別実装で**同じ出力契約**（`FeedbackReportV2`）を満たす。
- 各評価に**根拠となる発話区間**を付ける。改善例は本人が述べていない数字・事実を足さない（既存の性質試験を LLM 出力にも適用）。質問されなかった分野は明示（既存）。
- 表情・声色・見た目からの推定は禁止。人による評価が済むまで、「面接力の向上が確認できた」と書かない。

## 13. 性能・費用・品質の検証【C】（詳細：`docs/realtime-interview/EVALUATION_PLAN.md`）
初期目標（**未承認・未測定の目標**）：応答開始 p95 ≤ 2 秒／割り込み停止 ≤ 0.4〜0.5 秒／口の同期ずれ ≤ 150 ms／20 分の完走率 ≥ 95%／公式情報・安全性の負例で違反 0 件。費用はセッションごとの実請求額（`ProviderUsageRecord`）で測る。自然さ・追質問の教育的価値・評価の公平性は**人の評価が必要**。
