## 1. 制御プレーンとデータプレーンを分離
- **GitHubは開発の「制御情報」**：運用規約、コード、担当、署名済みの本人決裁記録、Issue #199と固定HEAD、PRレビュー。各AIはそれぞれ GitHub に読みに行き、ユーザーのChatGPT画面同期を待たない。秘密情報・受験生データ・権利上不明な原典全文・本番DBのコピーはGitHubへ置かない。
- **メインPCはデータの正本管理候補**：大学公式情報の検証済みDB、読み取り・監査・移行・復旧、バックアップ。既存外付けH:/I:には2026-11-08に切断/警告イベントがあり、現時点で大きな書込み/自動復元を避ける。バックアップの場所・暗号化・復旧責任者は別途設計。
- **ゲーミングPCは抽出の計算プレーン**：将来的には原典を読む→原典位置・版・スコープ・事実候補とUNKNOWNを出力→決定的な検査→隔離候補DB→人間/独立QAレビュー。モデル出力が直接`facts`正本に書き込むことは許さない。LLMとAntigravityの同時メモリ競合に注意し、今は`HOLD_REAL_MODEL_RUN.txt`を厳守。
- **Piは補助制御プレーン**：将来承認されたら小さいジョブ台帳・端末ステータス・実行要求の配送を担い、計算・原典・DB正本は保持しない。Piが停止してもGitHubで状態を復元でき、メインPCとゲーミングPCが人手で作業できる設計にする。

## 3. データ処理の将来像（実装・実行指示ではない）
```text
[GitHub: 規約/PR/Issue/固定SHA]
      ↓（各AIが直接読取、手動セッション起動）
[メインPC: 原典検証・DB正本候補] ←→ [ゲーミングPC: LLM候補抽出 + 独立QA]
```

- 大容量の資料やDBはPi/GitHubを中継しない。承認後、端末間の暗号化された必要最小限の転送経路を設計する。
- データの出典・ライセンス・版/取得時刻と適用年度、処理の再現ID、候補と検証済みの区別、最後の人間承認を常に保つ。
- Pi/ネットワーク/端末を「信頼の証拠」にしない。各工程の検証は処理元・固定SHA・原典の参照位置で行う。
