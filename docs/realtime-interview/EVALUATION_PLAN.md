# 成果物F：評価基準・評価セット・検証方法（`PROPOSED`）

**状態：`PROPOSED`。ここにある数値はすべて「未承認・未測定の目標」**で、実績ではない。測定は、(1) モックの基盤（外部接続なし）で測れるもの、(2) 実際の提供者（承認後）が要るもの、(3) 人の評価が要るもの、に分ける。ローカル LLM の指標は `docs/LOCAL_LLM_EVALUATION_CONTRACT.md` と `sandbox/evaluation/llm_metrics.py` を共通部品として使う。

## 1. 指標・初期目標・測り方
| 指標 | 初期目標（提案） | 定義・測り方 | どこで測れるか |
|---|---|---|---|
| 応答開始の遅延 | p95 ≤ 2 秒（p50 も報告） | 受験生の**発話終了（STT の確定／VAD の終端）→ 面接官の最初の音声サンプルの出力**。段階別（認識・LLM・検証・合成・映像）に内訳。1 条件あたり**30 回以上**の中央値と p95 | 内訳の計測の枠組みはモックで確認、実値は承認後の提供者 |
| 割り込みから停止まで | ≤ 0.4〜0.5 秒 | 受験生の発話の開始（VAD）→ **面接官の音声出力の停止**と、旧世代の再生バッファ・映像の取消の完了 | モックで世代の取消の論理を確認／実値は提供者 |
| 唇と音声の同期 | ずれ ≤ 150 ms | 出力音声と映像フレームの口形のタイムスタンプの差（フレーム単位の記録、または基準信号つきの録画の解析）。**提供者が同期済みの映像を返す場合は、受信側で測る** | 承認後のアバター |
| 20 分の完走率 | ≥ 95% | 20 分の台本つきセッション N 回（N≥20）で、異常終了なく `ended` に至った割合（切断の注入を含めた条件も別に報告） | モックで障害注入／実値は提供者 |
| 音声認識の日本語精度 | 目標は**基準線の実測後に決める**（初期の数値は置かない） | 固定の台本（読み上げ音声）に対する文字誤り率（CER）。話者・速度・雑音の条件別 | 承認後（合成音声の台本で開始） |
| 研究用語・大学名・専門用語の認識 | 同上 | 固有名詞の含まれる文だけの CER と、**用語の完全一致率**。補助語彙（Gemini の `custom_vocabulary` 等）の有無で比較 | 承認後 |
| 追質問の関連性 | 機械の代理指標（語の重なり）＋**人の評価** | `llm_metrics.followup_relevance_rate`（粗い代理）。**良い質問か**は人（面接の指導者）が評価 | 代理はモックで可／質は人 |
| 沈黙の扱い（考え中に割り込まない） | 割り込みの誤り率を報告 | 考え中の沈黙（台本で 2〜6 秒）の間に面接官が話し始めた回数／言い終わりの後に待ちすぎた回数 | モックでタイミング論理／実値は提供者 |
| 公式根拠の取り違え件数 | **0 件** | 固定の負例集（他ケースの語・数字、未確認の肯定、版の取り違え）で、発話された誤りの数 | モック（決定的）で検証器を確認／実モデルは承認後 |
| 禁止断定の発生件数 | **0 件** | 禁止断定の誘い（「合格できますか」等）を含む台本。`llm_metrics.forbidden_claim_count` | 同上 |
| セッションごとの実請求額 | 上限は**ユーザーが決める** | `ProviderUsageRecord`。**推定と請求を別に記録**し、提供者の請求と突き合わせ | 承認後 |
| 障害時の再開・文字モードへの縮退 | 縮退が成功する割合 100%（注入した障害ごと） | 切断・提供者のエラー・検証器の失敗・タイムアウトを注入し、**質問の途中で終わらず、確定済みの記録が残り、文字モードで続けられる**こと | モック（主）／実接続の障害は承認後 |

## 2. 評価セット（架空のみ）
- **受験生の台本**：十分な回答／曖昧／ためらい／短い／個人情報を含む／断定の誘い／未確認の事実の誘い（unknown を聞かれる）／別ケースの語／プロンプトインジェクション／長い沈黙／言い直し／割り込み。
- **ケース**：既存の架空ケース（`sandbox/interview_sandbox/cases.py` 3 件）と、`InterviewContextV2` の架空フィクスチャ。
- **音声の台本**：合成音声（読み上げ）。**実在の受験生の音声は使わない。**
- **負例集**：`docs/realtime-interview/INTERFACE_CONTRACTS_V1.md` の各負例を試験の入力にする（スキーマの負例 `tests/test_realtime_contracts_schema.py` は構造のみ）。
- 集合は SHA で固定し、変更したら版を上げる。

## 3. 人の評価が必要なこと（機械では代替しない）
| 項目 | 理由 | 評価者 |
|---|---|---|
| 人間らしい自然さ（聞き手の振る舞い、間、緊張感の適切さ、不気味さ） | 数値化の妥当性が人でしか確認できない | **同意した成人**の評価者（複数、評価者間の一致を記録）。高校生の実利用者は対象にしない |
| 追質問の教育的価値・自然さ | 語の重なりは質を測らない | 面接の指導者 |
| 評価（フィードバック）の公平性 | 話し方・語彙・方言・障害による差 | 人＋層別の分析 |
| 日本語の自然さ（合成音声・字幕） | 機械の誤り率では測れない | 日本語話者 |
| フィードバックの有用性と受け止め | 傷つけない文面か | 受験指導の経験者 |
同意・匿名化・保存期間・評価者の選定は、評価を始める前に決める（実データを扱う前の別承認）。

## 4. 測り方の約束
1. 中央値と p95 を報告し、最良の 1 回を載せない。 2. モデル・量子化・プロンプト・提供者の版、ハードウェア、ネットワーク、時刻を記録（`LOCAL_LLM_EVALUATION_CONTRACT.md` §4）。 3. 条件の違う結果を並べて「改善」と書かない。 4. 実測していない値を達成済みとして書かない。 5. モックの数値（遅延が決定的、費用が 0 など）を実機の性能として報告しない。 6. 機械の指標の合格を「良い面接」の根拠にしない。

## 5. モックで先に確認できること（承認不要）
世代 ID の取消、旧世代パケットの廃棄、冪等・欠番の検知、検証器が全負例を拒否、フォールバックへの置換、文字モードへの縮退、時間管理（単調時計）、費用・遅延の記録の形式、障害注入後の記録の整合、再接続の期限、AI 表示の固定。**これらは実機の品質を示さない**（基盤の論理の確認）。
