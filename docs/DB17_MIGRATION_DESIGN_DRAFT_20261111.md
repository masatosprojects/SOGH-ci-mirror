## 1. 現状の事実（コードを読んで確認）

1. master の連鎖は `0002`〜`0010`（`src/db_contract/additive_schema.py` の `MIGRATIONS`）。0011・0012 の SQL は master に無い。
2. **連鎖は『順序つきの接頭辞』**（`verify_history`）：適用済みの一覧は連鎖の先頭からの連続でなければならない（欠番・飛ばし・別順序は DRIFT）。`PRAGMA user_version` は最後に適用した ID の番号と一致しなければならない。**移行番号は適用順そのもの**で、先に適用された DB は、後から挿入された若い番号を取り込めない。
3. 各移行は凍結ファイル＋SHA-256 の固定。適用後に編集しない。`verify_schema_state`（DB-17）は、適用済みの移行が作ったオブジェクトの存在とSQLの一致、および**所有接頭辞（`trg_` `ux_` `ix_` `v_`）を持つのに、どの移行も作っていないオブジェクト**を報告する。
4. 番号の候補が衝突している：
   | 候補 | 出典 | 状態 |
   |---|---|---|
   | 0011 alias provenance（`alias_provenance_bundles`／`source_representations`＋8ガード） | PR #285（Draft）。SQL の SHA `1cf76e79974ac05855bb4f0491e24612f478b4320aa5c9a09f96d5327e630904`（ブランチのファイルから計算） | 凍結ファイルあり、未マージ |
   | 「0012」F-2 アーカイブ（`work_f2_` 接頭辞） | F-2 契約・プロトタイプ試験（#285 で 0011→0012 に改番済み） | 試験内のプロトタイプのみ |
   | 「0012」未確認FAQ証拠の保管枠 | STR-100（設計構想） | 未設計 |
   | g7 隔離ステージング（表3＋ガード10） | PR #306（Antigravity、修正中） | 連鎖の外 |
   | g6 版系列・影響（表2＋ガード3） | PR #306（同上） | 連鎖の外 |
   → **「0012」を名乗る構想が2つ、番号を持たない候補が2つ**。このままではどれが先に入っても残りが番号の飛ばしまたは衝突になる。
5. **STR-107 が数える『13オブジェクト』は、DB-17 が実際に報告したトリガー（g7 10＋g6 3）だけ**。実体は **表 5（g7 3：`quarantine_staging_candidates`、`_quarantine_approval_seals`、`canonical_facts_staging_target`／g6 2：`source_document_series_editions`、`series_revision_article_impacts`）＋トリガー 13 ＝ 18 オブジェクト**。表は接頭辞が所有名前空間（`trg_` `ux_` `ix_` `v_`）に無いため、**DB-17 は連鎖の外の表を検出しない**（独立QAで 10＋3 のみ報告された理由）。→ **DB-17 自体の検出の穴**であり、g7/g6 を連鎖に載せるだけでは再発を防げない。
6. 追加で確認した事実：g7/g6 の `SCHEMA_SQL` は `CREATE … IF NOT EXISTS` を `init_*_schema()` から呼ぶ方式（実行時に表を作る）。移行は『凍結ファイル＋事前検査＋履歴＋`user_version`』が契約。この二つは両立しない（実行時作成を残すと連鎖が把握できない）。

## 2. 設計上の要請（満たすべき条件）

- R1：すべての永続オブジェクトは、いずれか一つの凍結移行が作る（実行時の `init_*` は DDL を持たない）。
- R2：DB-17 は **表を含む**『移行の外のオブジェクト』を検出する（所有接頭辞の拡張、または表の許可リスト方式）。
- R3：番号は『適用順』。**実DB／実コピーに適用した番号は改番しない**。未適用の間は改番できる（現在、0010 より先は実DBに適用なし）。
- R4：STR-100：`storage_cycle`（管理上の収納先）と `proven_applicability`（公式に証明された適用範囲）を混同しない。`facts.case_id NOT NULL` は変更せず、未確認FAQの証拠は `facts` に入れない（別表）。
- R5：g7 の承認の権威は呼び出し側から書けない（QA の G7-R1／R2 の修正をスキーマに織り込む）。
- R6：途中失敗は全体ロールバック、予期しないオブジェクトは fail closed（既存の `apply()` の挙動を保つ）。
